# Deadline Rescue repository guidance

## Product design source of truth

Before changing user-facing UI, read `DESIGN_DIRECTION.md`. Treat it as the persistent visual and interaction brief for the whole app.

- The project is currently in Phase 1. Do not build speculative screens, sample states, visual components, icons, illustrations, or interactions before their implementation phase.
- Apply the direction only to UI that the user explicitly asks to build or restyle.
- Keep the interface calm, spacious, direct, and encouraging.
- Preserve Deadline Rescue's original identity. External productivity apps are inspiration for hierarchy and clarity only; do not reproduce their layouts, copy, branding, or illustrations.
- Keep the primary workflow obvious: capture work, confirm time, see the next session, focus on one thing.
- Design mobile-first, then use desktop space for context rather than simply stretching mobile cards.
- Core actions must remain keyboard accessible, readable without colour, and comfortable at touch sizes.
